# koharu-torch

`koharu-torch` runs Koharu's libtorch models. It's a fork of `tch` 0.26
[tch-rs] (libtorch 2.13) whose libtorch is loaded when the runtime starts
rather than linked, so one Koharu binary picks the CPU, CUDA, ROCm, or Metal
build of libtorch that fits the machine. `koharu-torch-sys` holds the C
bindings and their loading; the C++ shim they call is built and released from
`koharu-rs/torch`, and Koharu binds a release as it is.

Upstream `tch` can't be used as it is: its `torch-sys` links libtorch at build
time, with no option to load it at run time [tch-sys build].

## Generation

| Rule | Evidence |
|---|---|
| The C headers are the shim release's own, copied into `koharu-torch-sys`. | the release the runtime pins [shim release] |
| The Rust wrappers are generated by upstream's generator (`gen/gen.ml`) at its pinned commit from libtorch's `Declarations.yaml`, with Koharu's changes kept as a patch to the generator, and nothing generated is edited by hand. | `AGENTS.md`; `gen.ml` generates the wrappers [tch gen] |
| The shim exports every op; Rust wrappers are generated only for an allowlist of the ops Koharu calls (162 of 2,657), so adding an op needs no new shim. | `gen.ml` already filters ops by lists [tch gen filters] |

The headers and the runtime pin the same release, so they change together.
`load` resolves every bound function before any runs, so a shim that lacks
one fails to load.

## Errors

| Rule | Evidence |
|---|---|
| Ops return `Result<_, TchError>`; the panicking wrappers go, so an error inside a model reaches the caller as a value. | `tch`'s fallible `f_` ops [tch fallible] |
| The shim catches each `std::exception` and keeps its message, with libtorch's C++ backtrace, until `get_and_reset_last_err` takes it; it comes back as `TchError::Torch`. | the release's `PROTECT` [shim protect] |

The release binds no way to empty libtorch's caching allocator, so the memory a
dropped model held stays reserved for libtorch's next tensors rather than going
back to the driver for llama.cpp or stable-diffusion.cpp [PyTorch empty_cache].

## Loading weights

Loading fails on a missing weight and on an unexpected one, as either means
the port's names don't match the checkpoint (`AGENTS.md`). Two exceptions follow
upstream: a BatchNorm's `num_batches_tracked` may be missing, as PyTorch fills
it in [PyTorch batch norm], and `load_ignoring` leaves out the names a
transformers model lists in `_keys_to_ignore_on_load_unexpected`. Loaded values take
each variable's own type, so a model chooses its precision once. `no_grad` is a
guard that restores gradient tracking even when the closure panics.

## Changes from today

- The wrappers' generator and its patch live in this repository; today the
  generated wrappers carry hand edits and no generator.
- Ops return `Result`; today every op unwraps into a panic carrying a message.
- Loading fails on unexpected weights and keeps each variable's type.
- Unused code goes: `vision`, `jit`, the optimizers, `data`, `npy`, image
  input and output, CUDA's `synchronize`, the quantization engine, and Vulkan,
  which the shim is built without.
- `Tensor::shallow_clone`, which let safe code race on shared storage
  [tch race], goes; `alias` makes a new tensor over the same storage, as
  libtorch's `alias` does.
- This README replaces upstream's.
