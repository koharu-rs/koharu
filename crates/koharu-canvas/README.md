# koharu-canvas

The page viewport: it draws a page with the renderer at display rate and owns the camera, hit-testing, the selection, its handles, the brush cursor, stroke previews, and the tool gestures, so the desktop's web interface only picks tools and shows panels. It takes the W3C pointer events of `ui-events`, as the desktop translates CEF's, and answers with `cursor-icon`'s CSS cursors, while moves and edits leave as the scene's own ops. It reads the open project but never writes it: the host renders each frame, applies each edit the canvas returns, and puts the canvas's texture on screen, so every writer goes through one place. Each gesture reads the canvas and answers effects; the canvas applies the ones on its own selection and camera and passes the rest on, so a layer a tool makes arrives selected with the edit that makes it, while the brush and the tool stay the host's, which a request such as Alt and the wheel asks to change. The `view` example plays the host's part in a winit window, and its `--script` mode drives the canvas offscreen through a fixed set of gestures, for developing and checking the canvas alone.
