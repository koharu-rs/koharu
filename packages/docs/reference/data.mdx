## Supported formats

| Purpose             | Format                                   |
| ------------------- | ---------------------------------------- |
| Import              | PNG, JPEG, WebP, ZIP, CBZ, RAR, CBR, PDF |
| Flattened export    | PNG, a CBZ of PNG pages, or a PDF        |
| Layered interchange | PSD                                      |
| Working project     | One `.khr` file                          |

## Project data

Each project is one `.khr` file in the [projects folder](/guides/projects#create-and-reopen-projects). The file is a SQLite database holding the imported images, generated artwork, raster edits, and text. While a project is open, Koharu holds it locked and may keep a `-wal` file beside it.

<Warning>
  Do not change or copy a project file while it is open. Deleting a project from the start screen
  permanently removes its file.
</Warning>

## Settings and credentials

Settings live in `~/.koharu/config.toml`, a table per component: `[pipeline]`, `[providers]`, `[renderer]`, and `[agent]`. Settings you leave at their defaults are not written, so later default changes reach you. A value that doesn't read, such as one of the wrong type or a model that no longer exists, falls back to its default. A file that isn't valid TOML is an error; fix it or delete it. See [every key](/reference/settings#configuration-file).

API keys and provider sign-ins are encrypted in `~/.koharu/secrets.age`. Its key is kept in the operating system's credential store; on Linux that needs a Secret Service such as GNOME Keyring, KWallet, or KeePassXC. If the key is lost, the file cannot be read again and is deleted, so you sign in again. A project backup includes no keys or sign-ins.

Sign-ins to the [gallery](/guides/gallery)'s sites are cookies in Koharu's built-in browser. On macOS, the key they are encrypted with is **Koharu Safe Storage** in the keychain.

## Runtime and model store

Runtime packages and model files are stored in the `store` folder in Koharu's installation folder on Windows, or in `%LOCALAPPDATA%\koharu\store` when that folder isn't writable, and in `koharu/store` under the operating system cache folder on macOS and Linux. This data is replaceable: removing it while Koharu is closed makes the required files download again.

Never remove the store while Koharu may still have its libraries loaded.

## Logs

Koharu writes a log file of its INFO messages and above to `%LOCALAPPDATA%\Koharu\logs` on Windows, `~/Library/Logs/Koharu` on macOS, and `~/.local/share/Koharu/logs` on Linux. See [troubleshooting](/reference/troubleshooting) for more detailed logs.

## Back up safely

<Steps>
  <Step title='Close the project'>Finish current work before copying its file.</Step>
  <Step title='Copy the project file'>
    Copy the `.khr` file. A PSD or CBZ export is not a project backup.
  </Step>
  <Step title='Save settings separately'>
    Copy `config.toml` if needed. Reconnect providers through Koharu on the restored machine.
  </Step>
</Steps>
