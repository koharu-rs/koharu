description: 'Diagnose a problem and collect the information needed to reproduce it.'
---

Start with the complete error in the activity center or the error message. Identify the failing stage before changing project files or the store.

<AccordionGroup>
  <Accordion title="The first run does not finish">
    The first time a model runs, Koharu downloads the runtime packages for your GPU and the model's weights. Let active downloads in the activity center finish and confirm that GitHub, PyPI, AMD's repository, and Hugging Face are reachable.

    If it fails repeatedly, close every Koharu process, update the GPU driver, restart the computer, and retry on a stable network. Capture the complete error.

    Do not remove the store while a process may have its libraries loaded.

  </Accordion>

  <Accordion title="A model download fails">
    Check access to the model's Hugging Face repository and the free disk space for the store. Proxies, regional filtering, antivirus scanning, or interrupted writes can block downloads.

    Retry the same model once. If the same file fails, include the repository, filename, and full error in your report.

  </Accordion>

<Accordion title='Models do not run on my GPU'>
  Koharu uses the best GPU it finds and fails rather than falling back to another, and it has no
  CPU-only mode. Check that the driver meets the requirements in [hardware](/hardware), and read the
  error for the GPU it tried. On a Vulkan-only machine, detection, OCR, and LaMa run on the CPU by
  design.
</Accordion>

<Accordion title='A model runs out of memory'>
  Koharu does not unload models to make room, so a model that does not fit fails and names the free
  memory. Choose a smaller model, or switch the other stages to lighter models in **Settings →
  Pipeline** so the heavier ones unload, then retry. **Edit → Unload Models** frees every model
  Koharu loaded, as before a large fill; each loads again when it's next needed.
</Accordion>

<Accordion title='Detection or OCR misses text'>
  Check that the page is upright and readable. Inspect the detected text blocks before changing OCR
  models. Adjust thresholds conservatively across several pages and run detection again, try a
  manga-specific recognizer for Japanese, and correct source text before translating again.
</Accordion>

<Accordion title='Inpainting damages artwork'>
  Paint a smaller Remove area and avoid bubble borders and line art. Try LaMa before a heavier
  generative model. Clear the layer selection before painting so touch-ups go to a new raster layer.
</Accordion>

<Accordion title='A translation provider fails'>
  Verify the key, sign-in, or base URL in **Settings → Providers**, then reopen the processing
  selector. For a compatible server, check that the base URL ends where OpenAI's `/v1` does, and
  turn **Vision** off if the model does not accept images.
</Accordion>

<Accordion title='Koharu Agent cannot run'>
  Choose a model in the Agent panel; only models that call tools are offered. Check its provider's
  connection in **Settings → Providers**, and cancel a request before retrying.
</Accordion>

<Accordion title='Text is missing or malformed'>
  Confirm the text block has a translation, is visible, has nonzero opacity, and uses a font
  covering the target script. Source text is never drawn.
</Accordion>

  <Accordion title="Export differs from the canvas">
    Capture the affected page, format, a canvas screenshot, and the exported image. Canvas and exports draw through the same renderer, so a meaningful mismatch should be reported.
  </Accordion>
</AccordionGroup>

## Find the log file

Koharu writes messages of INFO and above to `koharu.log`, in this folder:

| Platform | Folder                                                                                   |
| -------- | ---------------------------------------------------------------------------------------- |
| Windows  | `%LOCALAPPDATA%\Koharu\logs`                                                             |
| macOS    | `~/Library/Logs/Koharu`                                                                  |
| Linux    | `$XDG_DATA_HOME/Koharu/logs`, or `~/.local/share/Koharu/logs` if that variable isn't set |

To open the folder, paste its path into File Explorer's address bar on Windows, or into **Go → Go to Folder** in Finder on macOS.

The file carries over from one launch to the next, and its times are in UTC. When it reaches 1 MB, Koharu deletes it and starts a new one, so copy it soon after the problem.

Before sharing, replace credentials, private filenames, and private page text with `[removed]`, keeping surrounding diagnostics. Include your OS, Koharu version, intended action, reproduction steps, and approximate error time.

Attach the log to a [GitHub issue](https://github.com/koharu-rs/koharu/issues) or ask on [Discord](https://discord.gg/mHvHkxGnUY). To report from the app instead, choose **Help → Send Feedback**, describe what happened, and add a screenshot if it helps.

## Get more detailed logs

Close Koharu, since launching it while it runs only brings the open window forward, then start it from a terminal with `RUST_LOG` set:

<CodeGroup>

```powershell Windows (PowerShell)
$env:RUST_LOG="debug"; & "$env:LOCALAPPDATA\Koharu\koharu.exe"
```

```bash macOS
RUST_LOG=debug /Applications/koharu.app/Contents/MacOS/koharu
```

```bash Linux
RUST_LOG=debug koharu
```

</CodeGroup>

If Koharu is installed elsewhere, use its path instead.

`RUST_LOG` takes a level, such as `debug` or `trace`, or [filter directives](https://docs.rs/tracing-subscriber/latest/tracing_subscriber/filter/struct.EnvFilter.html#directives), such as `info,koharu_pipeline=debug`. The extra messages appear only in the terminal; the log file keeps to INFO and above.
