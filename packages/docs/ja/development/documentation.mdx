---

ドキュメントは `packages/docs/` 内の Mintlify ワークスペース `@koharu/docs` です。依存関係はリポジトリのルートにある `bun.lock` で管理します。

<Steps>
  <Step title="ツールを導入する">
    Node.js 24 LTS と Bun 1.3.14 以降を使い、リポジトリのルートから実行します。

    ```bash
    bun install --frozen-lockfile --ignore-scripts
    ```

  </Step>
  <Step title="プレビューする">
    ```bash
    bun run docs
    ```

    `http://localhost:3001` を開きます。MDX や設定を変更すると表示が更新されます。

  </Step>
  <Step title="リンクを確認する">
    `packages/docs` で実行します。

    ```bash
    bun x mint broken-links
    ```

  </Step>
</Steps>

## ネイティブ MDX を書く

各ページの frontmatter に `title` と `description` を設定します。通常の記事のタイトルは Mintlify が描画するため、H1 として重複させません。サイトは Mintlify 自身のドキュメントに倣い、`luma` テーマ、`assets/logo-light.svg` と `assets/logo-dark.svg` のロゴ、Lucide のアイコンを使います。Mintlify のドキュメントと同じく、ページとサイドバーのグループにはアイコンを付けず、カードの `icon` にだけ [Lucide](https://lucide.dev/icons) の名前を指定します。ホームページは `frame` モードを使って本文に H1 を 1 つ設け、`assets/home/` のイラストから各セクションへリンクします。イラストにはライト版と `-dark` 版があります。

上部のタブも入れ子のグループも使わず、サイドバーはセクションを平らに並べた 1 つのリストです。ページは読者がしようとしていることに合ったセクションに属します。

| セクション           | フォルダー                | ここに置くページ                                                                                   |
| -------------------- | ------------------------- | -------------------------------------------------------------------------------------------------- |
| はじめに             | ルート                    | インストールから最初のページの書き出しまでを案内します                                             |
| 翻訳ワークフロー     | `guides/`                 | アプリでの作業を順に説明します                                                                     |
| モデルとプロバイダー | `models/`                 | 各工程で動かすモデルを選び、接続します                                                             |
| Koharu Agent         | `agent/`                  | エージェントの設定と使い方を扱います                                                               |
| しくみ               | `how-it-works/`           | 翻訳する人に向けて Koharu がそう動く理由を説明し、末尾に担当クレートの README へのリンクを置きます |
| 開発                 | `development/`            | ビルド、コードの担当範囲、開発への参加を扱います                                                   |
| リファレンス         | `reference/` と `privacy` | 設定、キー、ショートカット、保存場所、対処法を調べるためのページです                               |

しくみのページには、コードが実際に行うことだけを、アプリの用語と結果を説明する数値を使って書きます。設計の残りと出典はクレートの README に任せます。

手順には **Steps**、OS やモデルの選択肢には **Tabs**、必要な補足には **Note**・**Tip**・**Warning**、次の行動には **Columns** に並べた **Card**、症状別の回答には **Accordion**、レイヤーやフォルダーのツリーには **Tree**、設定キーには **ResponseField** を使います。表と Mermaid のコードフェンスを使い、独自のスクリプトや CSS に依存させません。

内部リンクは `/ja/guides/export` のようにルート相対で拡張子を省きます。共有画像は言語フォルダーの外へ置き、内容を説明する alt テキストを付けます。

## 翻訳をそろえる

既定の言語は英語で、`packages/docs/` 直下に置きます。日本語は `ja/`、簡体字中国語は `zh/` に置き、英語と同じファイル名とディレクトリ構造を使います。スラッグ、操作手順、例、技術情報を 3 言語でそろえます。本文だけでなく見出し、説明、部品ラベル、ナビゲーション、画像説明も翻訳します。

テーマとナビゲーションは `packages/docs/docs.json` が担当します。`navigation.languages` の各言語は同じ `groups`、つまりページを持つセクションを持ち、英語は `default: true` を維持します。ページを追加したら全言語のナビゲーションの該当セクションへ登録し、英語のパスには言語の接頭辞を付けず、翻訳のパスには付けます。同じページパスを複数の言語で使わないでください。構成は Mintlify の[国際化ガイド](https://www.mintlify.com/docs/guides/internationalization)を参照してください。言語切り替えは Mintlify の標準機能を使い、旧 Zensical のルートやリダイレクトは残しません。

## 公開を接続する

Mintlify ダッシュボードで `koharu-rs/koharu` を接続し、公開ブランチを選びます。Git Settings の **docs.json is in a subdirectory** を有効にして、末尾のスラッシュなしで `/packages/docs` を入力します。カスタムドメインに `koharu.rs` を指定し、Mintlify に表示された DNS 設定に従います。接続後は、ドキュメントを変更する push が公開ブランチに届くたびにサイトが公開されます。

<Note>公開とドメイン有効化には Mintlify の GitHub 連携とドメイン設定が必要です。</Note>

Mintlify の [monorepo 設定](https://www.mintlify.com/docs/deploy/monorepo)と[カスタムドメイン](https://www.mintlify.com/docs/customize/custom-domain)を参照してください。
