## 前提条件

Koharu は Rust 1.97.1（2024 edition）、Bun 1.3.14、LLVM 22.1.8 で開発しています。リポジトリはこれらのバージョンを固定していません。LLVM は `-sys` crate の bindgen が必要とする libclang を提供します。ネイティブライブラリ自体は実行時に取得するビルド済みパッケージのため、C++ ビルドシステムは不要です。

<Tabs>
  <Tab title='Windows'>ネイティブ依存関係用に MSVC の C/C++ ビルドツールを導入します。</Tab>
  <Tab title='Linux'>
    CI ワークフローが使うパッケージを導入します: `build-essential`、`libgtk-3-dev`、`libxdo-dev`、
    `libssl-dev`、`libayatana-appindicator3-dev`、`librsvg2-dev`。テストには `fonts-noto-cjk`、
    `dbus-x11`、`gnome-keyring` も必要です。
  </Tab>
  <Tab title='macOS'>
    ネイティブ依存関係が要求するプラットフォームの C/C++ 開発ツールを導入します。
  </Tab>
</Tabs>

## 開発を開始する

```bash
git clone https://github.com/koharu-rs/koharu.git
cd koharu
bun install
bun dev
```

`bun dev` は Next.js UI と Tauri を起動します。wasm-pack で `koharu-canvas` を WASM 向けに `packages/bridge/src/wasm` へビルドした後、`koharu-canvas` と `koharu-rasterizer` を監視して変更時に再ビルドします。成功すると Turbopack がブラウザークライアントを更新します。debug ビルドは CEF のリモートデバッグを `http://127.0.0.1:4000` で公開します。

## 変更した部分を確認する

最小限の debug チェックか対象テストを一度実行します。

```bash
cargo check -p koharu
cargo test -p koharu-pipeline <test_name>
cargo fmt --all --check
```

フロントエンドでは該当パッケージの対象テストや型チェックを使います。`bun run check` は整形チェック、`bun run lint` はフロントエンドの lint です。

<Note>
  全テスト、debug 以外のプロファイル、E2E
  テストは既定では実行しません。明示的に依頼された場合だけ実行します。
</Note>

## IPC バインディングを再生成する

Rust のコマンド署名と Specta 型が正本です。

```bash
cargo run -p koharu-app --bin generate
```

`packages/bridge/src/protocol.ts` を手動編集しないでください。

## 実行ファイルをビルドする

リリース実行ファイルが必要な場合、`bun run build` が `tauri build --no-bundle` を実行し、`target/release` に出力します。インストーラーはリリースワークフローで作成します。
