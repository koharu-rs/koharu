翻訳の設定は**設定 → 翻訳**で選びます。処理セレクターでもモデルと対象言語を設定できます。設定は Koharu の設定に保存され、すべてのプロジェクトに適用されます。プロバイダーの接続と認証情報はリクエストごとに読み込まれます。

## 言語とシステムプロンプト

**対象言語**を選びます。**システムプロンプト**はモデルに渡す指示で、`{target}` は対象言語の英語名に置き換わり、必ず含める必要があります。固有名詞、用語、口調、代名詞、翻訳しないテキストなどの指示を加え、OCR を直した後に複数のページで試してください。既定値は Index-Translate 自身の翻訳指示です。

LFM3 1.7B は対応する対象言語が限られています。その他のローカルモデルとホスト型モデルは、Koharu が提供するすべての対象言語を受け付けます。

## ページの翻訳のされ方

翻訳は開いているプロジェクトごとに 1 つの会話です。ページ順に 1 ページずつ進むため、各ページはそれまでに翻訳したページを踏まえます。選択したテキストブロックの翻訳も同じ会話の 1 ターンです。モデル、対象言語、プロンプトを変えると新しい会話になります。

各ページは読み順に並べたテキストとして送られ、回答にはそのすべてを含める必要があります。形式が崩れた回答、抜けたテキスト、空の翻訳があると、そのページは失敗します。著作権表記のように、モデルがそのまま返したテキストは元の文字を残します。そのクリーンアップは非表示になり、翻訳は付きません。

## オプション

| オプション | 内容                                                                                               |
| ---------- | -------------------------------------------------------------------------------------------------- |
| ビジョン   | 長辺 1,280 ピクセルのページ画像をテキストの前に送ります。既定ではオフです                          |
| 推論       | 選んだレベルでモデルに回答前の推論をさせます。**プロバイダーの既定値**はモデル自身の設定を使います |

ビジョンは画像を読めるモデルでだけ使えます。それ以外のモデルでは実行が失敗し、**ビジョン**をオフにするよう求められます。どちらのオプションも時間がかかり、Index-Translate 9B を使った Koharu のテストではどちらも訳質は上がらなかったため、残す前に数ページで試してください。

## ローカルの量子化

Koharu のローカルモデルは既定の量子化を読み込みます。別の量子化を使うには、`~/.koharu/config.toml` の `[pipeline.translator]` で、モデル名の後にコロンで量子化を指定します（例: `model = "koharu/index-translate-9b:Q8_0"`）。小さいファイルほど必要なメモリは少なくなりますが、通常は品質が下がります。ホスト型プロバイダーの配信精度は各社が管理します。

生成された翻訳は編集可能なプロジェクトデータのままです。書き出す前に[文面とページのレイアウトを確認](/ja/guides/review)してください。
