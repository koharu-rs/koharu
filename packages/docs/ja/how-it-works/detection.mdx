検出はスキャンを一度読み、ページの構造を書き込みます。コマ、吹き出し、そしてテキストと擬音ごとのテキストブロックです。続いて OCR が各ブロックの文字列を読みます。後の工程はすべて、この 2 つが書いたものから始まります。

## 検出が見つけるもの

RF-DETR のセグメンテーションモデルである **Koharu Layout HighRes** は、ページ上の 4 種類のもの、テキスト、擬音、吹き出し、コマを見つけます。それぞれに枠、ピクセル単位のマスク、信頼度があります。種類ごとのしきい値を下回る検出は捨てられます。**設定 → パイプライン**のしきい値は、既定ではモデル自身の値です。モデルは同じものを 2 回予測することがあるため、同じ種類でより信頼度の高い検出とほとんど重なるものや、別のテキストの中に入れ子になったテキストは、重複として捨てられます。

## 読み順

検出は、日本のマンガの読者と同じ順にページを並べます。コマごとに読み、あるコマのテキストをすべて読んでから次のコマへ進みます。コマ同士の間でも、コマの中のテキスト同士の間でも、ページを余白で分けて上から下へ読む段にし、それができなければ右から左へ読む列にして、それぞれの部分を同じ方法で並べます。

- 枠の 4 分の 1 以上がコマの中にあるテキストは、そのコマで読まれます。
- コマの横にはみ出した吹き出しや余白のキャプションのように、ほとんどがどのコマの外にもあるが、あるコマの横にあるテキストは、その高さの半分以上にわたる最も近いコマと一緒に読まれます。

この順序は**ストーリー**の並び順で、翻訳がモデルにテキストを送る順序でもあります。左から右へ読む本では、**レイヤー**で行をドラッグして正しい順に並べてください。

## 吹き出しとその部屋

吹き出しの輪郭は、そのマスクからなぞって作られます。吹き出しに複数のテキストがある場合、輪郭はテキストごとに 1 つの部屋に分けられ、各翻訳は自分の部屋に置かれます。

- 重なって描かれた 2 つの吹き出しは、まず輪郭が交わるくびれ同士を結ぶ線で分けられます。
- それでも 1 つの部分を共有するテキストは、テキストの間で細くなるところで分けられます。

部屋がどのように翻訳の枠になるかは[訳文の収め方](/ja/how-it-works/lettering)を参照してください。

## 各テキストブロックが受け取るもの

| フィールド | 検出が書き込むもの                                                                                      |
| ---------- | ------------------------------------------------------------------------------------------------------- |
| 位置       | 吹き出しの中、またはコマやページの上に単独で                                                            |
| 役割       | テキスト、または擬音                                                                                    |
| 枠         | 文字を囲む枠                                                                                            |
| 方向       | 傾きを考慮して文字のまとまりが縦に長ければ縦書き                                                        |
| 傾き       | まとまりの縁で最も多い向き（45° 以内）。行の先端を線幅ほども動かさない傾きは、傾きなしとみなされます    |
| 文字       | 大きさ、線幅、インクの色、縁取りの色                                                                    |
| マスク     | 文字のピクセル。輪郭の細い断片も覆うよう 3 ピクセル外まで広がりますが、ほかのテキストの枠には入りません |

絵の上の文字は、黒の周りを白で縁取るように、縁取りされていることがよくあります。Koharu は、囲んでいるものの周りを一周しているのがどちらの色かで、縁取りとインクを見分けます。翻訳はその後、同じ色で、縁取りを線として文字を入れます。

マスクが隣の枠に入らないのは、ブロックのクリーンアップがマスク越しに見えるからです。そこにクリーンアップがあると、隣の翻訳を覆ってしまいます。2 つのマスクの両方にかかる字形は、枠が近いほうのブロックに属します。

## 検出をやり直す

検出は、誰が作ったかにかかわらず、ページのコマ、吹き出し、テキストブロックを置き換えます。ただしロックしたものは別です。ロックしたレイヤーは、それを含むコマや吹き出しとともにそのまま残り、検出は残したブロックの上に 2 つ目のブロックを追加しません。しきい値を変えるなどして検出をやり直す前に、仕上げたテキストをロックしてください。

## OCR

OCR は、各ブロックの枠内のスキャンから原文を読みます。枠が隣の文字にかかることがあるため、切り抜いた範囲にあるページ内のほかのブロックの字形は、先に切り抜きの中央値の色で塗りつぶされます。OCR は待っているページを最大 8 ページまとめて読みます。

| 認識エンジン | 読めるもの                   |
| ------------ | ---------------------------- |
| Hayai OCR    | 日本語、中国語、韓国語、英語 |
| Manga OCR AR | 日本語のマンガ               |
| Baberu OCR   | 日本語のマンガ               |

OCR が読むのは存在するテキストブロックだけです。検出が見落としたテキストは、認識エンジンを替えても取り戻せません。

## 見落としがあるとき

| 見えるもの                 | 対処                                                                                     |
| -------------------------- | ---------------------------------------------------------------------------------------- |
| ブロックのないテキスト     | **テキストブロック**（`K`）で描き、**ストーリー**のメニューからその **OCR** を実行します |
| 順序の違うテキスト         | **レイヤー**でドラッグします                                                             |
| 検出が多すぎる、少なすぎる | 代表的な数ページでしきい値を変え、それらのページで検出をやり直します                     |
| 読み取りの誤り             | **ストーリー**で**原文**を直し、そのテキストを翻訳し直します                             |
| 絵にかかったマスク         | **レイヤー**でブロックのマスクを選んで消します。クリーンアップはすぐに隠れます           |

設計と出典: [`koharu-ml` の README](https://github.com/koharu-rs/koharu/blob/main/crates/koharu-ml/README.md)と [`koharu-pipeline` の README](https://github.com/koharu-rs/koharu/blob/main/crates/koharu-pipeline/README.md#2-stages)。
