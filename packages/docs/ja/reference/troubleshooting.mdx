description: '問題を切り分け、再現に必要な情報を集めます。'
---

アクティビティセンターまたはエラーメッセージに出た完全なエラーから確認します。プロジェクトファイルやストアを変更する前に、失敗した工程を特定してください。

<AccordionGroup>
  <Accordion title="初回の実行が終わらない">
    モデルを初めて実行するとき、Koharu は GPU 用のランタイムパッケージとそのモデルの重みをダウンロードします。アクティビティセンターのダウンロードが終わるまで待ち、GitHub、PyPI、AMD のリポジトリ、Hugging Face に接続できることを確認します。

    何度も失敗する場合は、Koharu のプロセスをすべて終了し、GPU ドライバーを更新してコンピューターを再起動し、安定したネットワークで再試行します。完全なエラーを記録してください。

    プロセスがライブラリを読み込んでいる可能性がある間は、ストアを削除しないでください。

  </Accordion>

  <Accordion title="モデルのダウンロードに失敗する">
    モデルの Hugging Face リポジトリへのアクセスと、ストアのディスク空き容量を確認します。プロキシ、地域によるフィルタリング、ウイルス対策ソフトのスキャン、書き込みの中断によってダウンロードが妨げられることがあります。

    同じモデルを一度だけ再試行します。同じファイルで失敗する場合は、リポジトリ、ファイル名、完全なエラーを報告に含めてください。

  </Accordion>

<Accordion title='モデルが GPU で動かない'>
  Koharu は見つけた最適な GPU を使い、別の GPU には切り替えずに失敗します。CPU
  だけで動かすモードもありません。ドライバーが[ハードウェア](/ja/hardware)の要件を満たしているか確認し、エラーに示された
  GPU を確認してください。Vulkan だけのマシンでは、検出、OCR、LaMa は仕様として CPU で動きます。
</Accordion>

<Accordion title='モデルのメモリが足りない'>
  Koharu
  は空きを作るためにモデルを解放しないため、収まらないモデルは空きメモリを示して失敗します。より小さいモデルを選ぶか、**設定
  →
  パイプライン**でほかの工程を軽いモデルに切り替えて重いモデルを解放し、再試行します。大きな塗りつぶしの前などに**編集
  → モデルをアンロード**を選ぶと、Koharu
  が読み込んだモデルをすべて解放します。モデルは次に必要になったときに読み込み直されます。
</Accordion>

<Accordion title='検出や OCR で文字が抜ける'>
  ページの向きが正しく、読み取れるか確認します。OCR
  モデルを替える前に、検出されたテキストブロックを確認します。しきい値は複数のページで慎重に調整して検出をやり直し、日本語にはマンガ向けの認識モデルを試し、翻訳し直す前に原文を修正します。
</Accordion>

<Accordion title='インペイントで画像が崩れる'>
  削除ツールで塗る範囲を小さくし、吹き出しの枠線や線画を避けます。重い生成系モデルより先に LaMa
  を試します。手作業の修正を新しいラスターレイヤーに分けるため、描く前にレイヤーの選択を解除します。
</Accordion>

<Accordion title='翻訳プロバイダーが失敗する'>
  **設定 → プロバイダー**でキー、サインイン、ベース URL
  を確認し、処理セレクターを開き直します。互換サーバーでは、ベース URL が OpenAI の `/v1`
  と同じ位置で終わっているか確認し、モデルが画像を受け付けない場合は**ビジョン**をオフにします。
</Accordion>

<Accordion title='Koharu Agent が動かない'>
  エージェントパネルでモデルを選びます。表示されるのはツールを呼び出せるモデルだけです。**設定 →
  プロバイダー**でそのプロバイダーの接続を確認し、再試行する前に実行中のリクエストをキャンセルします。
</Accordion>

<Accordion title='テキストが表示されない・崩れる'>
  テキストブロックに翻訳があり、表示されていて、不透明度が 0
  でなく、対象言語の文字をカバーするフォントを使っているか確認します。原文は描画されません。
</Accordion>

  <Accordion title="書き出しがキャンバスと違う">
    対象のページ、形式、キャンバスのスクリーンショット、書き出した画像を記録します。キャンバスと書き出しは同じレンダラーで描画されるため、明らかな違いは報告してください。
  </Accordion>
</AccordionGroup>

## ログファイルを探す

Koharu は INFO 以上のメッセージを `koharu.log` に書き込みます。保存先は次のフォルダーです。

| プラットフォーム | フォルダー                                                                  |
| ---------------- | --------------------------------------------------------------------------- |
| Windows          | `%LOCALAPPDATA%\Koharu\logs`                                                |
| macOS            | `~/Library/Logs/Koharu`                                                     |
| Linux            | `$XDG_DATA_HOME/Koharu/logs`。変数が未設定なら `~/.local/share/Koharu/logs` |

フォルダーを開くには、Windows ではエクスプローラーのアドレスバーに、macOS では Finder の**移動 → フォルダへ移動**にパスを貼り付けます。

ログは起動するたびに同じファイルへ追記され、時刻は UTC です。1 MB に達すると Koharu はファイルを削除して新しく書き始めるため、問題が起きたら早めにコピーしてください。

共有前に資格情報、非公開のファイル名、ページ本文を `[removed]` に置き換え、周囲の診断情報は残します。OS、Koharu のバージョン、目的、再現手順、エラーのおおよその時刻を添えます。

ログを [GitHub issue](https://github.com/koharu-rs/koharu/issues) に添付するか、[Discord](https://discord.gg/mHvHkxGnUY)で相談してください。アプリから報告するには、**ヘルプ → フィードバックを送信**を選び、起きたことを書いて、必要ならスクリーンショットを添えます。

## より詳しいログを取る

Koharu を終了してから（実行中に起動しても開いているウィンドウが前面に出るだけです）、`RUST_LOG` を設定してターミナルから起動します。

<CodeGroup>

```powershell Windows (PowerShell)
$env:RUST_LOG="debug"; & "$env:LOCALAPPDATA\Koharu\koharu.exe"
```

```bash macOS
RUST_LOG=debug /Applications/koharu.app/Contents/MacOS/koharu
```

```bash Linux
RUST_LOG=debug koharu
```

</CodeGroup>

別の場所にインストールした場合は、そのパスに置き換えてください。

`RUST_LOG` には `debug` や `trace` などのレベルか、`info,koharu_pipeline=debug` のような[フィルターディレクティブ](https://docs.rs/tracing-subscriber/latest/tracing_subscriber/filter/struct.EnvFilter.html#directives)を指定します。追加のメッセージはターミナルにだけ表示され、ログファイルは INFO 以上のままです。
