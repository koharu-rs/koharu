Koharu はすべてのモデルを 1 つの GPU で実行し、ページの描画にもその GPU を使います。その GPU に必要なネイティブライブラリとモデルファイルは自動でダウンロードされるため、リリース版の実行に CUDA や ROCm の SDK は不要です。

CPU だけで動くモードはありません。対応する GPU がなければモデルは動きません。Koharu はキャンバス、書き出し、サムネイルも GPU で描くため、プロジェクトを開くだけでも正常に動くグラフィックドライバーが必要です。

## 対応 GPU

<Tabs>
  <Tab title='NVIDIA'>
    Windows と Linux で CUDA 13.3 に対応しています。ドライバーが CUDA 13.3 以降に対応し、GPU の
    Compute Capability が 7.5 以上のとき、Koharu は CUDA GPU を使います。Turing 世代以降の GPU と
    R610 系列以降のドライバーが該当します。NVIDIA
    の[ドライバーとアーキテクチャの対応表](https://docs.nvidia.com/datacenter/tesla/drivers/cuda-toolkit-driver-and-architecture-matrix.html)と[ドライバーのダウンロード](https://www.nvidia.com/en-us/drivers/)を参照してください。
  </Tab>
  <Tab title='AMD'>
    x86-64 の Windows と Linux で ROCm 10.1 に対応していますが、対応状況は
    GPU、OS、ドライバーの組み合わせによって異なります。対応する [AMD
    ドライバー](https://www.amd.com/en/support)をインストールしてください。必要な ROCm ランタイムは
    Koharu がダウンロードします。プラットフォームの要件は AMD
    の[互換性マトリックス](https://rocm.docs.amd.com/en/docs-10.1.0/compatibility/compatibility-matrix.html)を確認してください。
  </Tab>
  <Tab title='Apple シリコン'>Apple シリコンの macOS では Metal を使います。</Tab>
  <Tab title='Vulkan'>
    Windows と Linux では、残る選択肢が Vulkan です。言語モデルと拡散系のインペイントモデルは Vulkan
    の GPU で動きます。libtorch には Vulkan 版がないため、Vulkan のマシンでは検出、OCR、LaMa が CPU
    で動き、そのぶん遅くなります。
  </Tab>
</Tabs>

GPU が複数あるときは、Koharu が最も良いものを選んで使い続けます。順位は [GPU で動くモデル](/ja/how-it-works/runtime#1-つの-gpu)を参照してください。

## 初回実行

| データ                                                      | ダウンロードされるとき                       |
| ----------------------------------------------------------- | -------------------------------------------- |
| libtorch、llama.cpp、stable-diffusion.cpp、CUDA または ROCm | いずれかのモデルを初めて実行したとき         |
| Hugging Face のコミットに固定されたモデルの重み             | そのモデルを初めて読み込んだとき             |
| Koharu のフォントデータセットのフォント                     | システムにない書体をテキストが必要としたとき |

ダウンロード元は、GitHub、CUDA は PyPI、ROCm は AMD のリポジトリ、重みとフォントは Hugging Face です。進捗はアクティビティセンターに表示されます。すべては 1 つのストアに入ります。[データの保存場所](/ja/reference/data#ランタイムとモデルのストア)を参照してください。

## メモリ

モデルは工程が初めて必要としたときに読み込まれ、読み込まれたままになります。場所を空けるためにアンロードはしません。収まらないモデルは失敗し、エラーに空きメモリが示されます。小さいモデルや量子化はメモリが少なくて済みますが、たいてい品質は下がります。ディスクに収まるモデルでも、GPU のメモリを超えることがあります。[メモリ](/ja/how-it-works/runtime#メモリ)を参照してください。

最初のモデルで実行が失敗した場合は、GitHub、PyPI、AMD のリポジトリ、Hugging Face にアクセスできるか確認し、ドライバーを更新して一度だけ再試行してください。それでも失敗する場合は、エラー全文を控えて[トラブルシューティング](/ja/reference/troubleshooting)に従ってください。
