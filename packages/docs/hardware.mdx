title: 'Hardware and runtimes'
description: 'Check that your GPU and driver can run Koharu, and what the first run downloads.'
---

Koharu runs every model on one GPU and draws pages with it. It downloads the native libraries and model files that GPU needs; you don't need a CUDA or ROCm SDK installed to run a release.

There is no CPU-only mode: without a supported GPU, models don't run. Koharu also draws the canvas, exports, and thumbnails on the GPU, so it needs a working graphics driver even to open a project.

## Supported GPUs

<Tabs>
  <Tab title='NVIDIA'>
    CUDA 13.3 is supported on Windows and Linux. Koharu uses a CUDA GPU when the driver reports CUDA
    13.3 or newer and the GPU has compute capability 7.5 or newer: a Turing-class or newer GPU with
    an R610-series or newer driver. See NVIDIA's [driver and architecture
    matrix](https://docs.nvidia.com/datacenter/tesla/drivers/cuda-toolkit-driver-and-architecture-matrix.html)
    and [driver downloads](https://www.nvidia.com/en-us/drivers/).
  </Tab>
  <Tab title='AMD'>
    ROCm 10.1 is supported on x86-64 Windows and Linux, depending on the exact GPU, operating
    system, and driver. Install a compatible [AMD driver](https://www.amd.com/en/support); Koharu
    downloads the ROCm runtime it needs. Check AMD's [compatibility
    matrix](https://rocm.docs.amd.com/en/docs-10.1.0/compatibility/compatibility-matrix.html) for
    platform requirements.
  </Tab>
  <Tab title='Apple silicon'>Koharu uses Metal on Apple-silicon macOS.</Tab>
  <Tab title='Vulkan'>
    Vulkan is the remaining option on Windows and Linux. Language models and the diffusion
    inpainters run on the Vulkan GPU. libtorch has no Vulkan build, so detection, OCR, and LaMa run
    on the CPU on a Vulkan machine, which is slower.
  </Tab>
</Tabs>

With more than one GPU, Koharu picks the best one and keeps it; see [models on your GPU](/how-it-works/runtime#one-gpu) for the order.

## The first run

| Data                                                        | When it downloads                          |
| ----------------------------------------------------------- | ------------------------------------------ |
| libtorch, llama.cpp, stable-diffusion.cpp, and CUDA or ROCm | The first time any model runs              |
| Model weights, pinned to a Hugging Face commit              | The first time that model loads            |
| Fonts from Koharu's font dataset                            | When a text needs a face your system lacks |

Downloads come from GitHub, PyPI for CUDA, AMD's repository for ROCm, and Hugging Face for weights and fonts. The activity center shows their progress. Everything goes into one store; see [data locations](/reference/data#runtime-and-model-store).

## Memory

A model loads the first time a stage needs it and stays loaded. Nothing is unloaded to make room: a model that doesn't fit fails, and the error names the free memory. Smaller models and quantizations need less memory, usually at some cost in quality, and a model that fits on disk can still exceed GPU memory. See [memory](/how-it-works/runtime#memory).

If a run fails at the first model, check network access to GitHub, PyPI, AMD's repository, and Hugging Face, update the driver, and retry once. If it fails again, capture the full error and follow [troubleshooting](/reference/troubleshooting).
