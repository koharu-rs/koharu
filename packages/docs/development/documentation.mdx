The documentation is the `@koharu/docs` Mintlify workspace in `packages/docs/`. Bun manages its dependencies through the repository's root `bun.lock`.

<Steps>
  <Step title="Install the docs tooling">
    Use Node.js 24 LTS and Bun 1.3.14 or later. From the repository root:

    ```bash
    bun install --frozen-lockfile --ignore-scripts
    ```

  </Step>
  <Step title="Preview">
    ```bash
    bun run docs
    ```

    Open `http://localhost:3001`. The preview updates when MDX or configuration changes.

  </Step>
  <Step title="Check links">
    From `packages/docs`:

    ```bash
    bun x mint broken-links
    ```

  </Step>
</Steps>

## Author native MDX

Every page needs a `title` and `description` in frontmatter. Mintlify renders article titles, so do not repeat them as an H1. The site follows Mintlify's own docs: the `luma` theme, the logo in `assets/logo-light.svg` and `assets/logo-dark.svg`, and Lucide icons. As in Mintlify's docs, pages and sidebar groups have no icon; only a card's `icon` is set, to a [Lucide](https://lucide.dev/icons) name. The homepage uses `frame` mode, provides its own single H1, and links each section from an illustration in `assets/home/`, which has a light and a `-dark` version.

The sidebar is one flat list of sections, with no top tabs and no nested groups, and a page belongs to the section that matches what its reader is doing.

| Section              | Folder                      | A page here                                                                                                        |
| -------------------- | --------------------------- | ------------------------------------------------------------------------------------------------------------------ |
| Get started          | the root                    | Takes a new user from install to a first exported page                                                             |
| Translation workflow | `guides/`                   | Walks through a task in the app                                                                                    |
| Models & providers   | `models/`                   | Chooses and connects the models each stage runs                                                                    |
| Koharu Agent         | `agent/`                    | Sets up and works with the Agent                                                                                   |
| How it works         | `how-it-works/`             | Explains why Koharu behaves as it does, for someone translating, and ends with a link to the owning crate's README |
| Develop              | `development/`              | Covers building, the code's ownership, and contributing                                                            |
| Reference            | `reference/`, and `privacy` | Lists settings, keys, shortcuts, locations, and fixes to look up                                                   |

A How it works page states only what the code does, in the app's own words, with the numbers that explain a result; the crate README keeps the rest of the design and its sources.

Use **Steps** for ordered tasks, **Tabs** for platform or model choices, **Note**, **Tip**, and **Warning** for relevant callouts, **Cards** in **Columns** for next actions, **Accordions** for symptom-specific help, **Tree** for a layer or folder tree, and **ResponseField** for configuration keys. Keep reference tables and fenced Mermaid diagrams readable without custom scripts or CSS.

Use root-relative internal links with no file extension, such as `/guides/export`. Shared images live outside the locale folders and need descriptive alt text.

## Keep translations aligned

English is the default language and lives directly in `packages/docs/`. Japanese and Simplified Chinese live in `ja/` and `zh/`, with the same filenames and directory structure as English. Maintain matching page slugs, instructions, examples, and technical coverage in all three languages. Translate headings, descriptions, component labels, navigation, and image descriptions as well as prose.

`packages/docs/docs.json` owns themes and navigation. Each language under `navigation.languages` has the same `groups`, a section each with its pages, and English keeps `default: true`. Add a page to its section in every language's navigation when it is introduced, using unprefixed paths for English and language-prefixed paths for translations. Each page path must belong to only one language. See Mintlify's [internationalization guide](https://www.mintlify.com/docs/guides/internationalization) for the structure. The site uses Mintlify's language switcher and does not keep old Zensical routes or redirects.

## Connect publishing

In the Mintlify dashboard, connect `koharu-rs/koharu` and select the production branch. In Git Settings, enable **docs.json is in a subdirectory** and enter `/packages/docs` without a trailing slash. Configure `koharu.rs` as the custom domain and follow the DNS records shown by Mintlify. Once connected, every push to the production branch that changes the docs publishes them.

<Note>
  Publishing and custom-domain activation require the Mintlify GitHub integration and domain
  configuration.
</Note>

See Mintlify's [monorepo setup](https://www.mintlify.com/docs/deploy/monorepo) and [custom domains](https://www.mintlify.com/docs/customize/custom-domain) for dashboard instructions.
