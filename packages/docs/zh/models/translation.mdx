在**设置 → 流水线**的**翻译器**部分选择翻译设置；处理选择器也可以设置模型和目标语言。这些设置保存在 Koharu 的设置中，对所有项目生效。服务商连接和凭据会在每次请求时读取。

## 语言与附加指示

选择**目标语言**。Koharu 的系统提示词是 Index-Translate 的英文翻译指示，要求模型把每页翻译成目标语言，并以同样的 JSON 回答。名称写法、术语、语气、人称代词或不应翻译的文字等要求，请写在**附加指示**中，可用任何语言和形式；Koharu 会按原样把它们附加在自己的提示词之后。修正 OCR 后请用多页测试。

LFM3 1.7B 支持的目标语言有限。其他本地模型和托管模型接受 Koharu 提供的所有目标语言。

## 页面如何翻译

每个打开的项目对应一段翻译对话：按页面顺序每页一轮，因此每一页都能参考之前已翻译的页面。模型收到的内容参见[翻译的工作原理](/zh/how-it-works/translation)。翻译所选文本块也是同一段对话中的一轮。更换模型、目标语言或附加指示会开始新的对话。

每页会按阅读顺序以文字列表发送，回答必须返回其中每一段。模型原样返回的文字（例如版权信息）会保留原来的字迹：其清理结果被隐藏，也不会生成译文。

以下情况 Koharu 会重试该页的翻译：

- 回答格式错误或缺少文字：重试一次。
- 回答照搬了上一页的译文：不带之前的页面重试一次。
- 提供商因内容拦截了该页或其回答：不带之前的页面重试一次，因为被拦截的可能是之前的页面。
- 页面超出或占满了模型的上下文窗口：丢弃之前页面中较早的一半后重试一次。
- 本地模型的回答被截断，例如不断重复：最多重试两次，并增加随机性，否则它会给出同样的回答。

重试后仍失败或译文为空的页面会保留未翻译状态，[任务继续](/zh/guides/processing)。使用托管模型时，每次重试都是一次新的请求。提供商过载或限制速率时，Koharu 最多会重新发送九次请求，总计约两分半钟，或按提供商要求的时间等待，之后任务才会结束。

## 选项

| 选项 | 作用                                                                                       |
| ---- | ------------------------------------------------------------------------------------------ |
| 视觉 | 在文字前发送长边 1,280 像素的页面图像；默认关闭                                            |
| 推理 | 让模型在回答前按所选等级进行推理；**提供商默认值**使用模型自身的设置，**关闭**则不进行推理 |

如果模型不支持所选的推理等级，例如始终推理的模型选择了**关闭**，运行会停止并指出该设置。视觉只适用于能读取图像的模型；其他模型翻译时不会收到页面图像。两个选项都会增加耗时，在 Koharu 使用 Index-Translate 9B 的测试中都没有提升译文质量，因此保留前请先在几页上试用。

## 本地量化

Koharu 的本地模型默认加载其默认量化。要换用其他量化，请在 `~/.koharu/config.toml` 的 `[pipeline.translator]` 中，在模型名后用冒号指定量化，例如 `model = "koharu/index-translate-9b:Q8_0"`。较小的文件需要更少内存，但通常会降低质量。托管服务商自行决定服务精度。

生成的译文仍是可编辑的项目数据。导出前请[检查措辞和页面版式](/zh/guides/review)。
