---
title: '硬件与运行时'
description: '确认你的 GPU 和驱动能否运行 Koharu，以及首次运行会下载什么。'
---

Koharu 在同一块 GPU 上运行所有模型，也用它绘制页面。它会自动下载该 GPU 需要的原生库与模型文件，运行发行版不需要安装 CUDA 或 ROCm SDK。

Koharu 没有纯 CPU 模式：没有受支持的 GPU 时，模型无法运行。画布、导出和缩略图也在 GPU 上绘制，因此即使只是打开项目，也需要能正常工作的显卡驱动。

## 支持的 GPU

<Tabs>
  <Tab title='NVIDIA'>
    Windows 和 Linux 支持 CUDA 13.3。只有驱动报告 CUDA 13.3 或更新版本，且 GPU 计算能力达到 7.5
    或更新时，Koharu 才会使用 CUDA GPU，即需要 Turing 架构或更新的 GPU，以及 R610
    系列或更新的驱动。查看 NVIDIA
    的[驱动与架构对应表](https://docs.nvidia.com/datacenter/tesla/drivers/cuda-toolkit-driver-and-architecture-matrix.html)并[下载驱动](https://www.nvidia.com/en-us/drivers/)。
  </Tab>
  <Tab title='AMD'>
    x86-64 的 Windows 和 Linux 支持 ROCm 10.1，具体取决于 GPU、系统与驱动的组合。请安装兼容的 [AMD
    驱动](https://www.amd.com/en/support)，Koharu 会下载需要的 ROCm 运行时。平台要求请查看 AMD
    的[兼容性表](https://rocm.docs.amd.com/en/docs-10.1.0/compatibility/compatibility-matrix.html)。
  </Tab>
  <Tab title='Apple 芯片'>Apple 芯片的 macOS 上使用 Metal。</Tab>
  <Tab title='Vulkan'>
    Vulkan 是 Windows 和 Linux 上的其余选项。语言模型和扩散类修补模型会在 Vulkan GPU
    上运行。libtorch 没有 Vulkan 版本，因此在 Vulkan 机器上，检测、OCR 和 LaMa 会在 CPU
    上运行，速度较慢。
  </Tab>
</Tabs>

有多块 GPU 时，Koharu 会选出最好的一块并一直使用；顺序参见[在 GPU 上运行的模型](/zh/how-it-works/runtime#一块-gpu)。

## 首次运行

| 数据                                                         | 下载时机                   |
| ------------------------------------------------------------ | -------------------------- |
| libtorch、llama.cpp、stable-diffusion.cpp，以及 CUDA 或 ROCm | 首次运行任何模型时         |
| 固定到 Hugging Face 某个提交的模型权重                       | 首次加载该模型时           |
| Koharu 字体数据集中的字体                                    | 文字需要系统中没有的字面时 |

下载来源为 GitHub、CUDA 来自 PyPI、ROCm 来自 AMD 的软件源，权重和字体来自 Hugging Face。活动中心会显示下载进度。所有内容都放在同一个存储中，参见[数据位置](/zh/reference/data#运行时与模型存储)。

## 内存

模型在某个阶段首次需要时加载，并保持加载。不会为腾出空间而卸载模型：放不下的模型会失败，错误信息会给出可用内存。更小的模型和量化需要的内存更少，但通常会牺牲一些质量；能放进磁盘的模型，仍可能超出 GPU 内存。参见[内存](/zh/how-it-works/runtime#内存)。

如果在首个模型处失败，请检查能否访问 GitHub、PyPI、AMD 的软件源和 Hugging Face，更新驱动后重试一次。如果仍然失败，请记录完整错误并按照[故障排除](/zh/reference/troubleshooting)操作。
