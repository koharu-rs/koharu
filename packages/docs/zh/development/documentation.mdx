文档是位于 `packages/docs/` 的 Mintlify 工作区 `@koharu/docs`，由仓库根目录的 `bun.lock` 管理依赖。

<Steps>
  <Step title="安装文档工具">
    使用 Node.js 24 LTS 和 Bun 1.3.14+，从仓库根目录运行：

    ```bash
    bun install --frozen-lockfile --ignore-scripts
    ```

  </Step>
  <Step title="预览">
    ```bash
    bun run docs
    ```

    打开 `http://localhost:3001`，MDX 或配置更改后会自动更新预览。

  </Step>
  <Step title="检查链接">
    在 `packages/docs` 中运行：

    ```bash
    bun x mint broken-links
    ```

  </Step>
</Steps>

## 使用原生 MDX

每页 frontmatter 都需要 `title` 和 `description`。普通文章标题由 Mintlify 渲染，不要重复添加 H1。站点参照 Mintlify 自己的文档：使用 `luma` 主题、`assets/logo-light.svg` 与 `assets/logo-dark.svg` 中的标志，以及 Lucide 图标。与 Mintlify 的文档一样，页面和侧边栏分组都不设图标，只有卡片的 `icon` 填写 [Lucide](https://lucide.dev/icons) 的图标名。首页使用 `frame` 模式，在正文中提供唯一的 H1，并用 `assets/home/` 中的插图链接到各个部分；每张插图都有浅色版和 `-dark` 版。

侧边栏是一列平铺的部分，没有顶部标签页，也没有嵌套分组；页面归入与读者正在做的事相符的部分。

| 部分         | 文件夹                    | 放在这里的页面                                                     |
| ------------ | ------------------------- | ------------------------------------------------------------------ |
| 开始使用     | 根目录                    | 带新用户从安装走到导出第一页                                       |
| 翻译流程     | `guides/`                 | 按步骤讲解应用中的一项操作                                         |
| 模型与服务商 | `models/`                 | 选择并连接各阶段运行的模型                                         |
| Koharu Agent | `agent/`                  | 设置和使用 Agent                                                   |
| 工作原理     | `how-it-works/`           | 为翻译者解释 Koharu 为何如此运作，并在末尾链接所属 crate 的 README |
| 开发         | `development/`            | 构建、代码归属与参与贡献                                           |
| 参考         | `reference/` 和 `privacy` | 供查阅的设置、键、快捷键、位置和解决方法                           |

工作原理页面只写代码实际做的事，使用应用自己的用语和能解释结果的数字；其余设计和出处留在 crate 的 README 中。

顺序任务使用 **Steps**，平台或模型选择使用 **Tabs**，必要提示使用 **Note**、**Tip**、**Warning**，下一步入口使用放在 **Columns** 中的 **Card**，按症状组织的帮助使用 **Accordion**，图层或文件夹树使用 **Tree**，配置键使用 **ResponseField**。参考表格和 Mermaid 代码围栏应易读，不依赖自定义脚本或 CSS。

内部链接使用无扩展名的根相对路径，例如 `/zh/guides/export`。共享图片放在语言目录外，并提供描述性替代文本。

## 保持翻译一致

英语是默认语言，直接位于 `packages/docs/`。日语和简体中文分别位于 `ja/`、`zh/`，使用与英语相同的文件名和目录结构。保持页面路径、操作步骤、示例与技术覆盖一致。正文之外，标题、描述、组件标签、导航和图片说明也要翻译。

`packages/docs/docs.json` 管理主题和导航。`navigation.languages` 中的每种语言都有相同的 `groups`，即各自带有页面的部分，英语保留 `default: true`。新增页面时应加入所有语言导航中对应的部分，英语路径不加语言前缀，翻译路径加上对应语言前缀。每个页面路径只能属于一种语言。具体结构见 Mintlify 的[国际化指南](https://www.mintlify.com/docs/guides/internationalization)。站点使用 Mintlify 原生语言切换，不保留旧 Zensical 路由或重定向。

## 连接发布

在 Mintlify 控制台连接 `koharu-rs/koharu` 并选择生产分支。在 Git Settings 中启用 **docs.json is in a subdirectory**，输入不带结尾斜杠的 `/packages/docs`。添加自定义域名 `koharu.rs`，按 Mintlify 显示的记录配置 DNS。连接后，每次向生产分支推送修改文档的提交都会发布文档。

<Note>发布和域名启用需要 Mintlify GitHub 集成与域名配置。</Note>

控制台操作见 Mintlify 的 [monorepo 设置](https://www.mintlify.com/docs/deploy/monorepo)与[自定义域名](https://www.mintlify.com/docs/customize/custom-domain)文档。
